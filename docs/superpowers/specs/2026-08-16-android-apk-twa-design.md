# Android APK wrapper (Trusted Web Activity) — Design

## Goal

Package the existing web game (deployed at `https://cardgame-eta-five.vercel.app/`)
as an installable Android app that opens the live site full-screen, with no
browser chrome (no address bar / status indicators), so it feels like a
native app. Distribution for now is sideload (share the APK directly);
the approach must not preclude publishing to Google Play later.

## Chosen approach: Trusted Web Activity (TWA) via PWABuilder

A TWA is a thin native Android shell (backed by Chrome) that renders a
web page full-screen once the app has proven, via a signed file hosted on
the domain, that it is the legitimate owner of that URL. No custom native
UI code is needed. The APK is generated by pwabuilder.com from the site's
PWA manifest — no local Android Studio/JDK install required for this
project.

**Rejected alternatives:**
- **Custom native WebView app (Kotlin/Android Studio):** far more effort
  (writing and maintaining an Android project) for no functional benefit
  over a TWA for this "just show the web page" use case.
- **Capacitor/Cordova hybrid wrapper:** unnecessary tooling overhead;
  only pays off if native device APIs (camera, push notifications, etc.)
  are needed, which they are not here.

## Scope of changes

1. **Web App Manifest** (`public/manifest.json`)
   - `name`: "Bitevní karty", `short_name`: "Bitevní karty"
   - `display`: `standalone`
   - `background_color`: `#17211a`, `theme_color`: `#17211a`
   - `start_url`: `/`
   - `icons`: multiple PNG sizes (48, 72, 96, 144, 192, 512px), including
     one `512x512` marked `"purpose": "maskable"` for adaptive icon support
2. **App icon set**
   - A new simple Napoleonic-styled icon (e.g. laurel wreath + crossed
     sabres or an ace motif in the game's gold/dark-green palette) will be
     authored as a single source SVG, then rasterized to the required PNG
     sizes via a small one-off Node script using the `sharp` package
     (dev-time only; not a runtime dependency of the app).
   - Icons are static assets checked into `public/icons/`.
3. **`app/layout.tsx`**
   - Add `<link rel="manifest" href="/manifest.json">` and appropriate
     `theme-color` / `apple-touch-icon` meta tags so the site is a valid
     installable PWA (this also benefits any user who adds the site to
     their home screen directly from a mobile browser, independent of the
     Android APK).
4. **`.well-known/assetlinks.json`**
   - Added as a static route/file once PWABuilder generates the signed
     Android package and provides the app's SHA-256 signing certificate
     fingerprint. This file is what allows the TWA to run with zero
     browser UI (Digital Asset Links verification). Until this file is
     live and matches, the TWA falls back to showing a URL bar.
   - This step depends on output from the external PWABuilder step (see
     Process below), so the fingerprint value is not known until then.

## Explicitly out of scope (for this iteration)

- Offline support / service worker (a "nice to have" for Play Store's PWA
  quality checklist, not required for a TWA to function).
- Google Play Store listing assets (screenshots, store description,
  content rating questionnaire) — deferred until the user decides to
  publish.
- Any native Android code/project in this repo — PWABuilder produces the
  APK/AAB directly from the hosted manifest; no Android project is
  committed to this repository.

## Process (manual steps outside the codebase, for the user)

1. Ship the manifest/icon/layout changes above; confirm production
   deploy is live.
2. Go to pwabuilder.com, enter the production URL, let it analyze the
   manifest, and generate a signed Android package (APK/AAB) using
   package name `cz.hradecak.bitevnikarty`.
3. PWABuilder provides the SHA-256 fingerprint for the generated signing
   key; add this to `.well-known/assetlinks.json` in the repo and deploy.
4. Install the downloaded APK on a device to verify full-screen (no URL
   bar) behavior once Digital Asset Links verification succeeds
   (may take a short propagation delay after deploying step 3).

## Testing / verification plan

- `npm run build` must remain clean after adding the manifest link and
  new static assets (no code changes to game logic).
- Manually verify in a browser dev tools "Application" panel that the
  manifest is discovered and valid (icons resolve, no manifest parse
  errors).
- Visual check that generated icons render correctly at small sizes
  (legible at 48x48, the smallest home-screen icon size on some Android
  launchers).
- Final end-to-end verification (TWA installs and opens full-screen) is
  a manual, outside-the-repo step performed by the user on an Android
  device per the Process section above, since it depends on PWABuilder
  and real device installation.
